# Task 8 Report: Room Schema Export and Migration Paths

## Result

Enabled reproducible Room schema export at the existing database version 6 and added migration
instrumentation coverage for every adjacent migration and every supported starting version through
version 6. The existing single `MIGRATION_5_6` remains unchanged and remains the only migration
that creates the aggregate indexes.

## Changes

- Applied the Room Gradle plugin and configured `app/schemas` as the schema export directory.
- Enabled `exportSchema` on `BreatheDatabase` without advancing the database beyond version 6.
- Added schemas 1–6 for `BreatheDatabase` and registered them as Android-test assets.
- Added the Compose BOM to the Android-test runtime classpath so instrumentation assets can merge
  and the existing versionless Compose test artifact resolves.
- Added a zero-data `UsageAccessReader` `@BindValue` to the existing Hilt Activity test. That test
  uninstalls the production module containing the binding, so the test component otherwise cannot
  assemble after Task 7 made usage access an injected boundary.
- Added `BreatheDatabaseMigrationTest`, covering:
  - every adjacent path: 1→2, 2→3, 3→4, 4→5, and 5→6;
  - every distinct path from a supported version to 6: 1→6, 2→6, 3→6, 4→6, and 5→6;
  - monitored-app row survival and the historical 15-second default;
  - custom `pauseSeconds` survival from schemas 4 and 5;
  - intervention-event survival, including the historical zero default and nonzero
    `minutesSaved` values;
  - intentional destruction of only the unused `quotes` cache at 4→5; and
  - both version-6 aggregate indexes.

## TDD evidence

### RED

The complete migration instrumentation suite was written before changing production or Gradle
configuration. `:app:compileDebugAndroidTestKotlin` succeeded because Room schema loading and
migration validation happen on the instrumented device rather than at Kotlin compilation time.
The configured SDK reported no attached device, no AVD, and no emulator binary, so the expected
runtime missing-schema failure could not be observed locally.

An Android-test packaging probe did expose the absent Android-test Compose BOM before it was added.
After that test-only dependency was corrected, the schema asset merge passed and all six JSON files
were present in the merged Android-test assets.

### GREEN

After enabling export, generating the historical schema fixtures, and registering the schema asset
directory, both production and Android-test Kotlin compilation passed. A forced Room/KSP rerun
left the committed schemas byte-for-byte unchanged.
